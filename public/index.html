FIELD PULSE // three measurements, never summed

Ollama, Ray, Jupyter, and a dozen stacks like them are answering the whole internet with nothing in front of them. Whoever finds one can spend your GPU, read your models, and on some of them run code on your machine. LeakyCompute measures how much of that is visible in public indexes and provides a local checker for infrastructure you control.

The three numbers below come from three different places: what an archived catalog claimed, what public indexes list today, and what bounded rolling re-verification has confirmed.

Defensive checklist

  • Network isolationBind Ollama to 127.0.0.1 or a private VPC. Never 0.0.0.0 on the public internet.
  • AuthenticationPut a reverse proxy (TLS + API key / mTLS) in front. Do not rely on “security through obscurity.”
  • Input validationReject model names with path traversal, URLs, or absolute filesystem paths.
  • Least privilegeNon-root container, read-only rootfs where possible, no access to cloud metadata.
  • DetectAlert on /api/pull spikes and model names containing ../, /etc, or link-local metadata IPs.

Methodology & ethics

LeakyCompute is a defensive research project. Public indexes nominate candidates; the system does not discover hosts by walking address space. Governed verification sends only bounded read-only requests and never ships exploit payloads or demonstrates impact. Researchers request GitHub-SSO lab access via issue; approval writes an allowlist entry used by the gated lab.
